## 一、核心发现：25 条「拼写变体」被误记为「异名/独立种分歧」

### 1.1 现象

三属的「名称分歧」（NCBI 保留独立 taxid、MycoBank 指向别的接受名）中，有 **25 条**其实是
**同一个名字的两种拼写**，MycoBank 自己在 `Name status` 列标为 **`Orthographic variant`**。

| 属 | 名称分歧条目 | 其中拼写变体 |
|---|---|---|
| Colletotrichum | 407 | **7** |
| Trichoderma | 421 | **8** |
| Diaporthe | 502 | **10** |
| **合计** | **1,330** | **25** |

逐条清单见 `拼写变体_25条.tsv`。

代表性例子：

| 声明名 | MycoBank 接受名 | 差异 |
|---|---|---|
| *D. parvae* | *D. parva* | 词尾 -ae / -a |
| *D. multigutullata* | *D. multiguttulata* | 少一个 t |
| *D. tuyouyou* | *D. eucommiae* | MycoBank 判为正写 |
| *C. duohuaense* | *C. duohuaense*（正写） | 拼写 |

### 1.2 影响（重算后）

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 发现总数 | 5,781 | **5,781**（不变） |
| 不一致（错值） | 1,532 | **1,532**（不变） |
| 不确定 | 3,891 | 3,891（不变） |
| **非错** | 164 | **189**（+25） |
| **矛盾** | 194 | **169**（−25） |
| 「异名/独立种分歧」类别 | 194（38 + 29 + 127） | **169（31 + 21 + 117）** |
| Diaporthe 裁决表的**真分歧** | 127 | **117** |
| 裁决表另列「拼写变体」 | — | **10 条** |

裁决表分级随之变为：

```
A 决定性 94 ｜ B 倾向性 9 ｜ C 待查 9 ｜ D 反向候选 1 ｜ I 同名异物 4 ｜ V 拼写变体 10
真分歧 = 94 + 9 + 9 + 1 + 4 = 117
已定性（A + I + D）= 99（不变）
不作结论（B + C）= 18（原 28）
```

## 二、为什么会漏掉（根因）

**不是疏忽，是「两套实现」——同一条判据写了两遍，其中一处写对、另一处没写。**

| 位置 | 判据 | 是否正确处理拼写变体 |
|---|---|---|
| `pipeline.py`（号层） | 查 MycoBank `Name status`，有 `_is_variant` 分支 | ✅ 有，但**放错了分支** |
| `sources.py`（四方核验） | 只比两个名字字符串：`accept.split()[-1] == name.split()[-1]` | ❌ 完全没查 status |

### 2.1 号层那条为什么也没兜住

```python
_is_variant = _st_myb.lower().startswith("orthographic")

if not _base_epi:            ...
elif _base_epi == sp_bare:   # ← 只有「基础种加词完全相等」才进这里
    if _is_variant: → 「拼写变体（非错）」
```

**`_is_variant` 只在种加词完全相同才被检查**——而种加词完全相同时本来就不需要拼写规则。
真正的拼写变体（种加词差 1–2 个字母）落进 `else:` → 判成「真·两个不同的种」。

### 2.2 四方核验那条完全没有这个概念

```python
same = accept.split()[-1].lower() == name.split()[-1].lower()
"verdict": "一致" if same else "分歧"
```

**纯字符串比较。** 而 `Name status` 就在同一份 MycoBank 导出的第 5 列，代码其他地方（同名异物）已经在用。

### 2.3 下游为什么没兜住

裁决表把 C 级写成「**未检索到修订文献**」——字面正确，但真实原因是：

> **这件事不需要论文：它们是同一个名字的两种拼写。**

「找不到文献」被当成了「证据不足」，实际是「**问题本身提错了**」。

### 必须写明的方法学限制

> 「未检索到支持合并的文献」是**否定性证据**，不等于「该合并是错的」。
> 真正定案需要 ① MycoBank 页面所列的异名参考文献（该站为 JS 渲染，本机抓不到）；
> ② 或模式株的多基因系统发育。

**本轮的“年代矛盾”检验不成立**：被合并的种比接受名晚发表，是异名的常态，不能作为过度合并的证据。
该方法已弃用，勿再引用。

## 七、附带修掉的一个数据安全缺口（比上面两条更要紧）

### 7.1 事故

`results/Colletotrichum/colletotrichum_三列表.tsv` 被发现**只剩 678 字节 / 3 行**（原件 136,825 字节 / 408 行）。

### 7.2 根因（已证实，不是"本地损坏"）

该目录下留有运行残留 `colletotrichum_进度.json`：

```json
{"genus": "Colletotrichum", "done": 3, "total": 3, "finished": true,
 "out_tsv": "results/Colletotrichum\\colletotrichum_三列表.tsv"}
```

**网页端「限制种数」默认值是 3**；有人把「输出目录」指到 `results/Colletotrichum` 后点了一次「开始」，
流水线就用 3 个种的结果**覆盖**了 408 行的正式结果表。

三个佐证：同目录另出现 `colletotrichum_metrics.json`（`n_species: 3`）与 `colletotrichum_证据.jsonl`，
且它们在 `out_v2/`（原始运行目录）里根本不存在。

### 7.3 已修（护栏）

`src/typeaudit/pipeline.py` 的 `write_tables()` 增加前置判断：

```python
_existing = 已有表的行数
if _existing and len(rows) < _existing:
    p1 = "<名>.partial.tsv"     # 原表一个字节都不动
```

**实测验证**：在一份 408 行的表上跑 3 行的部分运行 →

```
[report] ⚠️ 本次只产出 3 行，少于已存在的 408 行 —— 为免覆盖完整结果表，改写 partial
原表 137234 → 137234 字节 ｜ 未被覆盖: True
partial 文件行数: 3
```

### 7.4 仍需注意

护栏只防「**行数变少**」。若输出目录指向正式结果目录、且跑满整个属，仍会正常覆盖——
**看结果时不要把「输出目录」指到 `results/`**；那是展示用的发布目录，不是运行目录。
