# Bug 判别特征手册

> 这份文档回答一个问题：**下次再犯同类错误时，我怎么能一眼看出来？**
>
> 每条都写成「症状 → 判别特征 → 根因 → 正解」。**判别特征最重要**——
> 根因分析要花时间，而判别特征让你在三十秒内知道该往哪看。
>
> 全部来自本项目实测，不是从文档抄的。凡是没亲自踩过的，这里不写。

---

## 零、先记三条元规律（比任何单条都值钱）

**元规律一：静默失败比报错危险得多。**
本手册里超过一半的坑，共同形态是「不报错、不提示，但给出错的结果」。
报错会拦住你，静默会骗你。**所以凡是「过滤、查询、加载」，都要设计对账。**
典型：`SortColumn=""` 返回 0 条却不报错；空路径加载成空表，
而空表的后果不是「缺数据」，是「所有号都判成查无」。

**元规律二：看到假发现【成簇】出现，先怀疑解析/分词，别怀疑数据。**
真发现是散的（`FMR6273`、`HKUCC10928` 各不相同）；
假发现会挤在一起、共享同一段前缀（`PD88`、`PD92`、`PD93`…）。
一次「凭空 9 条假发现」就是这么来的。

**元规律三：同一件事有两套实现/两套判定，就是两套 bug。**
实测：归一化有两份实现 → 同一个号两条路径键不同；
判定有两套（pipeline 标记 vs 网页层裁决）→
同一个号左边标红「目录记为别种」、右边标绿「异名（非错）」。
**只留一份。**

## 一、接口与取数（静默失败最密集的地方）

### 1 查询参数没配齐 → 返回 0 条但不报错
- **症状**：接口 200，`TotalCount` 有值，`RecordEntityList` 是空的
- **判别特征**：**「它知道有多少条，但一条都不给你」**。这个组合几乎总是参数问题，不是权限问题
- **根因**：`SortColumn=""`（留空）时服务端走了一条不排序的代码分支，直接返回空
- **正解**：`SortColumn` 必须给非空值（如 `"name"`）

### 2 字段名给错 → 记录照返回，字段值全空
- **症状**：记录条数正常，但每个 `ListFields` 都是 `[]`
- **判别特征**：**「行数对、格数全空」**——不是数据缺，是你没要到
- **根因**：`Fields` 里写了网页源码里的短名（`e13`/`name`），服务端只认长数字 FieldKey（`14682616000000219`）
- **正解**：用长数字 FieldKey；短名一律无效

### 3 操作符名大小写敏感，写错了被静默忽略
- **症状**：条件写进去了，`TotalCount` 却是全量
- **判别特征**：**过滤后的总数和不过滤一模一样** ⇒ 条件根本没生效
- **根因**：`"Contains"` 是大小写敏感的；写 `"contains"` 服务端不报错、直接当没写
- **正解**：用 `"Contains"`；**并且每次过滤都要对账 TotalCount**（实测：大写得 850，小写得 62751）

### 4 无效操作符一律静默返回全量
- **症状**：同 3
- **判别特征**：同 3。实测无效的有 `Starts with` / `Ends with` / `Like` / `Is in list` / `Does not contain`
- **正解**：生效的只有 `Contains` 和 `=`。**不知道有没有生效时，拿一个必然为 0 的条件做对照**

### 5 多条件查询：三条同时满足才生效
- **症状**：给了两个条件，结果只按第一个算（或 HTTP 503 / `Success:false`）
- **判别特征**：结果恰好等于「只给第一个条件」的结果
- **根因**：每个条件要有 `Index`（从 0 递增）；第一个条件 `OperatorOfCondition` 为空串、后面的填 `"Or"`；`ComplexQuery` 必须**列全**（`"Q0 Or Q1"`）
- **正解**：三条齐备。实测：或=1348/与=835 与手算完全吻合，可用来验证

### 6 返回格式与预期不符 → 解析出 0 条
- **症状**：请求成功、字节数不小，但解析出的记录是 0
- **判别特征**：**响应体开头是 `<?xml` 或 `<INSDSeq` 而不是 `LOCUS`**
- **根因**：`rettype="gbc"` 返回的是 XML，不是 GenBank 平文件
- **正解**：用 `rettype="gb"`；分批 efetch 时每批 ≤150 个 id

## 二、归一化与键（最容易造成「张冠李戴」）

### 7 归一化删掉了有语义的符号 → 不同实体撞成同一个键
- **症状**：查 A 返回 B 的记录，且不报错
- **判别特征**：**两个看起来不同的号，归一化后字符串相同**（`CBS 100.06` → `CBS10006`，`CBS 10006` → `CBS10006`）
- **根因**：删点归一化。实测目录 62,761 行只有 60,052 个不同键 ⇒ **2,709 行在撞车里被覆盖**
- **正解**：**点必须保留**（它在 CBS 编号里有语义：`CBS 100.06` 是 100 号第 06 支、`CBS 10006` 是 10006 号，是两株不同的菌）；撞车时**绝不静默覆盖**，判为「无从核验」

### 8 归一化保留了无语义的符号 → 去重失效
- **症状**：同一个号在表里占两格（`LLTA- 01` 与 `LLTA 01`）
- **判别特征**：两格只差一个格式符号，其余全同
- **根因**：短横被当成有语义保留下来
- **正解**：**点保留、短横去掉**。区分标准是「这个符号有没有语义」，不是「好不好看」

### 9 归一化只删了标签的括号、留下了内容
- **症状**：同一个号在两条代码路径下得到不同的键
- **判别特征**：**同一输入，两个函数的输出不同** —— 这就是「两套实现」的信号
- **根因**：`MFLU<THA>` 只删尖括号 → 留下 `THA`，于是 `MFLU090228` vs `MFLUTHA090228`
- **正解**：删掉**整个 `<...>` 标签**；并把两份实现合并成一份（`norm_bare` 直接委托 `norm_key`）

### 10 「先按距离取前 N、再过滤」——顺序错了会丢掉想要的候选
- **症状**：明明有正确答案，工具却报「找不到」
- **判别特征**：**目标候选的排序位置在后，被 limit 截掉了**（实测目标编辑距离 2，而限量 8 被一堆同样距离 2、但字母序更靠前的候选占满）
- **根因**：过滤发生在截断之后
- **正解**：**先过滤候选域、再排序取前 N**（给 `nearest_codes` 加 `only=` 参数）

## 三、判定逻辑

### 11 「形近」只对「不在登记表里」的东西才有意义——顺序反了会把真机构纠成假机构
- **症状**：`CMM 3814`（真实机构）被判成「书写错误（应为 ICMP 3814）」
- **判别特征**：**被纠错的代码，本身在机构登记表里查得到** ⇒ 顺序反了
- **根因**：把纠错放在了「查登记表」之前。`_lev("CMM","ICMP")=2`，于是真机构被纠成另一家
- **正解**：**第一步永远是问「这个机构存不存在」**；存在 ⇒ 无目录（无从核验）；不存在 ⇒ 才谈「代码写没写错」
- **额外代价**：这条 bug 还会把荒谬的更正号写进受信表，污染下游

### 12 号码级穷举纠错会给出假纠正
- **症状**：「应为 CBS 6995」「应为 ICMP 8578」
- **判别特征**：**更正值比原号短**；且原号本身可能是真号（实测 `ICMP 18578` 是真号，被纠成 `8578`）
- **根因**：**号越短越可能存在**，「改一位后能查到」不构成证据
- **正解**：只做**代码前缀**纠错（有独立证据：代码不在登记表 + 候选在）；**数字原样带过去**，绝不动数字

### 13 用启发式去筛本该由权威决定的东西
- **症状**：真值被当噪声丢掉
- **判别特征**：**换一个启发式，结果就翻一遍**；而且在**已知的真值**上直接翻车
- **根因**：试过三种自动筛同义属的方法，三种都在已知真同义属上错：
  `Name status=Synonym` 计数恒为 0（那列根本不是同义标记）；`mutual` 双向互挂把 `Gloeosporium`（真同义属）标成噪声；`cur/n` 比值把 `Gloeosporium` 当独立大属剔除
- **正解**：自动化只生成**候选**，裁交给**权威**（MycoBank/登记表）或人。硬编码清单也一样有召回缺口（`BASIONYM_GENERA` 只有 3 个属，漏掉 `Gnomonia`）

### 14 沿「接受名链」只走一步
- **症状**：`Gnomonia cingulata` 被判成「目录记为别种」，其实它最终归属声明属
- **判别特征**：**上一个名字的接受名，本身还有接受名**
- **根因**：MycoBank 的 `Current name` **不一定是终点**（实测链条两跳：`Gnomonia cingulata → Glomerella cingulata → Colletotrichum gloeosporioides`）
- **正解**：**走到不动点**（限次迭代，去掉作者部分再查下一跳）

### 15 两套判定器给出相反结论
- **症状**：同一张卡左边标红「目录记为别种」、右边标绿「异名（非错）」
- **判别特征**：**同一个实体上有两个来源的结论**，而且没人规定谁优先
- **根因**：pipeline 写标记、网页层现算裁决，两套逻辑
- **正解**：**统一到一套**，另一套的值保留在 `raw_flag` 里备查（不丢信息）

### 16 带动态值的标记，前端不要做字符串匹配
- **症状**：`书写错误（应为 CGMCC 3.17361）` 归错栏
- **判别特征**：标记里**括号内容随数据变**
- **正解**：归类**由后端统一解析**（精确匹配 → 前缀匹配 → 保守默认「不确定」），前端只读 `cls` 字段

### 17 保守默认的方向：没判过的一律「不确定」
- **症状**：新出现的标记被当成「通过」
- **正解**：**兜底方向必须是「不确定」而不是「非错」**。语料没判过的标记，一律进不确定栏

## 四、工程与代码

### 18 `let` 同名重复声明 → 整段 JS 失效，所有按钮点不动
- **症状**：页面能打开、能滚、接口全 200，但**点任何按钮都没反应**
- **判别特征**：**服务端一切正常**（没有报错、没有 5xx）。这是纯浏览器端问题
- **根因**：`let TAB` 被声明两次 ⇒ `SyntaxError` ⇒ 整段脚本不执行
- **正解**：改完网页**先跑 `python tools\check_web.py`**（语法 + 顶层重复声明 + 元素 id 对账三合一）
- **注意**：函数内部的同名 `const` 是合法的，只有**顶层**重复才致命

### 19 `$('id')` 引用已删除的元素 → TypeError 中断事件处理
- **判别特征**：**只有某个特定按钮点不动**（而不是全部）
- **根因**：删了输入框，JS 里还在取 `.value`
- **正解**：`check_web.py` 的元素 id 对账会抓它

### 20 检查器本身不跳注释 → 假阳性
- **症状**：检查器报「元素缺失」，其实那只是注释里提到的
- **判别特征**：报的位置在注释行
- **正解**：先剥注释再扫；剥行注释时要避开 URL 里的 `://`

### 21 单字母变量名撞车
- **症状**：`'str' object has no attribute 'out'`
- **根因**：循环里写了 `a = ...`，而同一个函数的 `a` 是 argparse 命名空间
- **正解**：别用 `a`/`b` 当循环变量

### 22 `except Exception` 吞掉本该看见的错误
- **症状**：功能「静默不工作」，日志里什么都没有
- **根因**（两次实测）：
  ① `sources._entrez()` 在缺邮箱时抛的是 `SystemExit`，**`except Exception` 抓不到** ⇒ 线程静默死掉，界面上只剩一行「耗时 N 秒」，看起来像卡住
  ② 缺 `import json` 抛 `NameError`，被 `except Exception` 吞掉 ⇒ 所有条目报「尚未实现」
- **正解**：抓 `BaseException`；catch 里**至少要打一行字**；读失败不能静默变空字典

### 23 `dict[k] = v` 在一对多关系上静默丢条目
- **症状**：同一份数据，两种算法算出不同的数（实测互相并名 13 vs 54）
- **判别特征**：**计数不稳定、换遍历顺序就变**
- **根因**：MycoBank 对一个学名可能有多行，`byname[n] = c` 后写覆盖先写，把一对多压成一对一
- **正解**：一对多关系用**集合累加**（`setdefault(k, set()).add(v)`）

### 24 空路径 / 相对路径的静默陷阱
- **症状**：源加载成空表，或用了**不是你以为的那个文件**
- **判别特征**：`n_rows()==0` 但没报错；或产出与输入对不上
- **根因**：
  ① 配置里 `path: ""` 直接 `cls("")` ⇒ 空对象（而空表的后果是「所有号判成查无」）
  ② 相对路径按**配置目录**解析 ⇒ 找不到就**静默回退**到自动探测的另一份
  ③ 缓存目录传了 URL / 空串 ⇒ `makedirs` 失败或被 try/except 悄悄丢掉源
- **正解**：空路径也走回退；解析相对路径要两级查找；**打印绝对路径**；`raise` 而不是 `pass`

### 25 Windows MAX_PATH 260
- **症状**：`FileNotFoundError [WinError 3]`，且报错中文因 GBK 变乱码
- **判别特征**：**路径明显很长**（拼进了 20 个名称）；报错里路径被截断/乱码
- **正解**：长标识用**短哈希**（`sha256(...)[:8]`）而不是把名字全拼进去

### 26 插列之后还用旧列号
- **症状**：某一整列被覆盖成别的值
- **判别特征**：**整列统一变成了「另一个列的值」**
- **根因**：插了一列后 `q[6]` 指向的已经不是原来那一列
- **正解**：按**列名**取（`head.index("期望标记")`），不用列号

### 27 格式化字符串与解包的小雷
- `"{  }".format()` → `KeyError: '  '`
- `f(**d, x)` → `SyntaxError: positional argument follows keyword argument unpacking`
- `global X` 声明在函数中太晚 → `SyntaxError: name 'X' is used prior to global declaration`

### 28 行继续符与转义
- 非 raw 字符串里写 `\\` → 变成字面反斜杠，`SyntaxError: unexpected character after line continuation character`
- **重要**：`SyntaxError` 是**编译期**错误 ⇒ **整个脚本一行都不会执行**，包括它前面的文件写入。
  「我明明改了」但没生效时，先确认脚本是不是压根没跑

## 五、数据与科学判断

### 29 分词正则漏一个字符类 → 凭空造出成簇的假发现
- **症状**：一次报出 9 条「共享外部保藏号」，全是假的
- **判别特征**：**假发现成簇，且共享键总是同一段前缀**（`PD88`/`PD92`/`PD93`）
- **根因**：号码字符类不含 `/`，`PD 88/858` 被截成 `PD88`，7 条不同记录挤成一个键
- **正解**：号码部分允许 `/`、`.`、`-`；并且**看到成簇就先怀疑分词**

### 30 同一个号在不同列可以带不同标记
- **症状**：`CBS 132511` 在模式菌列是 `[未核]`、在菌株号列是 `[—]`，被当「干净」收进了受信表
- **判别特征**：**同一个号在两列出现，标记不一致**
- **正解**：**一票否决** —— 该号在任一列带过任何标记，就不算「核过且干净」

### 31 「没检查」被当成「检查通过」
- **症状**：`(strain) 19`、`2-11BP` 这类实验室编号进了受信表
- **判别特征**：**带 `[—]`（无标记）但没有机构前缀**
- **根因**：这些是 GenBank `/strain` 字段的值，**根本没进过检查流程**
- **正解**：`(strain)` 开头一律排除；**「无标记」只有在该号确实走完检查流程时才算通过**

### 32 受控词表的拼写错无法自动判
- **症状**：`Oomyceet`（应为 `Oomycete`）不会被自动发现
- **判别特征**：**词表里不存在正确拼法** ⇒ 任何「找相似对」的启发式都抓不到它（实测相似对全是 `1 months ~ 2 months` 这种垃圾）
- **正解**：这条只能**半自动** —— 自动导出完整词表（95 字段 / 585 取值），人工过一遍。当年就是靠人读出来的

### 33 把观察结果当成期望值 → 回归测试退化成同义反复
- **症状**：测试永远通过，且什么都没验证
- **判别特征**：**语料里的「期望值」的来源是这个工具自己的输出**
- **正解**：每条语料必须带「依据」，**依据必须来自工具之外**（登记表/目录/MycoBank/文献/人工判读）。
  判据一句话：**依据能不能在不跑这个工具的情况下核验？**

### 34 期望值只能由「外部依据或口径」的变化驱动
- **允许**：接入了新权威（ICMP 官方库）⇒ 期望值跟着变，依据列同步改写
- **禁止**：依据没变、只是工具输出变了 ⇒ 先查哪个对，**不能先改语料让它通过**（那是把 bug 封进测试里）

### 35 加了约定，所有比对点都要改
- **症状**：松散端同时报「语料未覆盖某标记」和「某标记有但没出现」——**自相矛盾**
- **根因**：语料用 `书写错误*`（前缀约定），而落差比对用精确匹配
- **正解**：约定（前缀/通配）一旦引入，**审计、落差、反向比对三处都要认它**

## 六、怎么往这份文档里加新条目

加之前先回答四个问题，答不全就别加：

1. **症状**能不能被一句话说清？
2. **判别特征**是什么？——**必须是一眼能看出的东西**（数字异常、成簇、矛盾、空白）。
   写不出判别特征，说明还没真懂这条 bug。
3. **根因**是机制层面的，还是只是「当时手滑」？后者不配进手册。
4. **正解**能不能落成机制（加进 `check_web.py` / 对账 / 断言），而不是靠自觉？

**最值钱的是「顺序敏感」和「静默失败」两类。** 本项目几乎所有的深水 bug 都落在这两类里：
- 顺序：先过滤再排序、先查存在再谈写错、先剥注释再扫
- 静默：不报错但给错结果 —— 一律用**对账**和**显式报错**对付
