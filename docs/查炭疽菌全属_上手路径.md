# 查炭疽菌全属（*Colletotrichum*）：上手路径

> 目标读者：拿到 `colleto-type-audit` 仓库、想审计**整个炭疽菌属**类型材料元数据的人。
> 本文只讲「从零到出结果」的操作路径；每条方法背后的实测依据见 `README.md`。

---

## 零、先选任务——别一上来就建树

「查炭疽菌全属」不是一个动作，是**六件事**。先看清你要哪一件：

| 你要什么 | 用哪个入口 | 规模 | 要不要联网 |
|---|---|---|---|
| ① 全属**物种级**审计：抽出各物种的类型指定、跑 J 规则 | `python -m typeaudit.audit --genus Colletotrichum` | 全属 293 名义种 | 要（或给本地语料） |
| ② 换属前的**可行性门**：这个属值不值得审 | `python -m typeaudit.gate --genus Colletotrichum` | 全属 | 要 |
| ③ 全属**号对账**：NCBI / 框架 / CBS 目录三源比对 | `python tools/reconcile_colletotrichum.py` | 293 行 | 要（CBS 目录可离线） |
| ④ **一株多名**检测：同一保藏号被标多个种名 | `python tools/check_multiname.py` | 任意提交 | 否（吃 gb/json） |
| ⑤ **并名裁决**：某两个名字该不该并，遗传证据 | `python tools/type_synonym_verdict.py` | **一次批量提交** | 要（+WSL 建树） |
| ⑥ **数字自洽**核验：文档里的数 ↔ 源表 | `python -m typeaudit.numbers` | 你自己的文档 | 否 |

**⚠️ 最重要的一条**：⑤ **不是**全属工具。它的 `--acc-range` 走的是**号段检索**，
只有「一次批量提交、数据同源」时才适用（本项目用的是 Weir et al. 2012 的
`JX009400:JX010500`，1047 条记录 / 76 株 / 23 物种）。
**要全属建树，得先按物种清单或保藏号清单取数**——见第六节。

## 二、任务①：全属框架审计（主力入口）

```bash
# 离线：分析一个本地语料目录（PDF 抽出的 txt 或 PMC XML 都可以）
python -m typeaudit.audit --genus Colletotrichum --corpus <你的语料目录> --out out

# 联网：按检索阶梯自动抓 PMC 全文再分析
python -m typeaudit.audit --genus Colletotrichum --fetch \
  --email you@example.org --max-papers 200 --out out
```

**六个阶段**：`acquire → gate → extract → rules → metrics → report`

**产物三件**：

| 文件 | 内容 |
|---|---|
| `<genus>_species.tsv` | 物种级记录（每行一个种，含类型指定、保藏号链） |
| `<genus>_findings.tsv` | J 规则候选（待人工裁定） |
| `<genus>_metrics.json` | 指标 + **口径** + 规则覆盖报告 |

**⚠️ 必读护栏（README 里的硬约束，这里再强调）**：

其一，**语料是 PMC XML / JATS 就走「文档序单元」路径**，不要在压平文本上正则切块：

```python
from typeaudit.textutil import segment
bl = segment(raw_xml, "Colletotrichum")   # XML 走单元，纯 txt 走 blocks
```

其二，**`<title>` 绝不能漏**——JATS 的种级标题就在里面，漏掉会让模式指定段被归到**上一个种**名下。

其三，**J 规则候选假阳性高**，只可用于**缩小候选集**，不是结论。尤其：
- `J-07 一号两主` 只可喂「该物种 `Typus` 段内声明的号」
- `J-08 位数孤例` 需要「同批同构」前提；**使用方应按保藏机构补一张「编号是否定宽」表**

其四，**`J-15` 是元规则**：报「检出 0」之前必跑。实测 12 篇里「类型材料字段」只枚举到 287 个号，
而全文含 2690 个类保藏号记号 ⇒ **2508 个号从未被检查**。

## 三、任务②：可行性门（换属时先做）

在投入审计前，先判断这个属的文献**写不写得出类型指定**：

```bash
python -m typeaudit.gate --genus Colletotrichum --batch --email you@example.org
```

**为什么重要**：`gate` 测三根轴，其中一根是「培养物型 vs 标本型」。
实测 166 条目 / 78 属：**培养物型抽出率 63%，标本型 0%**。
**标本型类群用这套等价链法做不出来**（不是调参问题）——遇见就换路（馆藏号正规化层，或改用 GBIF）。

## 四、任务③：全属号对账

```bash
python tools/reconcile_colletotrichum.py \
  --sim-pdf data/SiM2022_fulltext.txt \
  --errors data/副表1_错误清单.tsv \
  --registry data/cbs_catalogue.tsv \
  --cache .cache \
  --budget 600 \
  --out out/
```

**参数含义**：

| 参数 | 说明 |
|---|---|
| `--sim-pdf` | 框架论文全文（本项目 = Liu et al. 2022, Stud Mycol 101:1–56；**PDF 抽出的 txt**） |
| `--errors` | 已知错误清单（用于回归验证） |
| `--registry` | CBS 目录（`cbs_catalogue.tsv`） |
| `--cache` | 请求缓存目录（**重跑零请求**） |
| `--budget` | **时间预算（秒）**——防超时；实测 ~2.5 s/请求，别设太小 |
| `--limit` | 只处理前 N 个物种（试跑用） |
| `--no-manual` | 跳过人工裁定表 |

**⚠️ `--budget` 必须给**：100 物种的完整对账实测会超时（>270 s），且**要顺序跑不要跳步**，
否则缓存积累不起来、下一轮还得重下。

## 五、任务④：一株多名检测（通用，快）

**通用性最好**——不限定炭疽菌，任何 GenBank 提交都能吃。

```bash
# 输入一：GenBank flat file
python tools/check_multiname.py --gb records.gb --out multiname.tsv --mycobank data/mycobank_full.tsv

# 输入二：已解析的 json（免网络复跑）
python tools/check_multiname.py --json raw.json --out multiname.tsv --mycobank data/mycobank_full.tsv
```

**输出三档（grep 文字，勿改 emoji）**：

```
多名-1 异名（非错）                       Current name 相同
多名-2 两皆接受名（需查该菌株原始出处）      都是接受名且不同
多名-3 号重复使用（真错）                  同号下 strain/保藏号归一化后仍不唯一
```

**两条铁律**（踩过坑固化的）：

其一，**分组键一律用 `/culture_collection`，绝不用物种名**。
物种名会随分类学修订漂移——实测 164 株里 17 株「一株多名」。

其二，**判据用归一化值，展示用原始值，两套必须分开**。
`CBS 124.22` / `CBS124.22` / `CBS:124.22` 是同一个号；
`MFLUCC<THA>090551` 与 `MFLUCC:090551` 也是——**国家标签 `<THA>` 必须先剥掉**。

## 六、任务⑤：并名裁决（深挖个案，**按号段**）

```bash
W=work/
python tools/type_synonym_verdict.py fetch   --workdir $W --acc-range JX009400:JX010500
python tools/type_synonym_verdict.py prep    --workdir $W --min-genes 8 --species-map map.tsv
python tools/type_synonym_verdict.py align   --workdir $W
python tools/type_synonym_verdict.py tree    --workdir $W
python tools/type_synonym_verdict.py verdict --workdir $W --pair ICMP:18578 ICMP:18642
python tools/type_synonym_verdict.py plot    --workdir $W --pair ICMP:18578 ICMP:18642
```

**六阶段各自产物**（可断点续跑）：

| 阶段 | 产物 |
|---|---|
| `fetch` | `raw.json`（GenBank 记录） |
| `prep` | `panel_<gene>.fa`、`seqs.json`、`panel_index.json` |
| `align` | `panel_<gene>.trim.fa` |
| `tree` | `concat.fa`、`tree.treefile` |
| `verdict` | `verdict_*.tsv` |
| `plot` | `figures/tree_verdict.*`、`figures/distance_dist.*` |

**`--species-map` 是干什么的**：GenBank 的物种名会漂移，同一株的不同基因记录可能还留着旧名。
实测 `ICMP:10643` 一株三种写法（`camelliae` / `Glomerella cingulata` f.sp. `camelliae` /
`C. gloeosporioides` f.sp. `camelliae`），按 GenBank 名分组会把它和真 *gloeosporioides* 并到一起。

纠正表格式（**两列，按保藏号**）：

```
ICMP:10643	camelliae
ICMP:10646	camelliae
ICMP:18542	camelliae
```

**⚠️ 必须按保藏号，不能按种名**——按种名映射会误伤同名的其它株。

### 全属怎么办：号段不够

`--acc-range` 只覆盖**一次批量提交**。全属 293 种的数据散落在几百个提交里，所以要换取数方式：

| 方案 | 做法 | 现状 |
|---|---|---|
| **甲（推荐）** | 先用 `audit` / `reconcile` 找到**候选并名对**，只对候选对做建树 | 现成 |
| 乙 | 按**物种清单**逐个取该种 ex-type 的多基因记录 | **需改代码**：把 `fetch` 的号段检索换成「物种名 → 保藏号 → /culture_collection 反查」 |
| 丙 | 按**保藏号清单**批量取（如从 `cbs_catalogue.tsv` 提取） | **需改代码**：同上，换检索式 |

**改法提示**：`stage_fetch` 里那一行就是唯一的入口——

```python
term = "{}[ACCN] AND Colletotrichum[Organism]".format(a.acc_range)
```

把它换成「按物种名列表逐个 esearch」或「按保藏号列表 esearch」即可，
下游 `prep` / `align` / `tree` / `verdict` / `plot` **一行都不用改**
（它们只认 `raw.json`）。

## 七、任务⑥：数字自洽核验

```bash
python -m typeaudit.numbers --rules rules/example_rules.json \
  --docs-dir <你的文档目录> --data-dir <你的源表目录> --report out/report.tsv
```

规则**外部化**（写在 json 里）：你把「文档里该出现什么数」写成规则，
它去磁盘上读文档、读源表、自己重算、比对。

**为什么值得做**：本项目实测，一次「改一处忘了下游」的级联漏改，
是靠核数器（而不是靠人眼）捞回来的。**核数器不看过程，只看磁盘上的东西是否自洽。**

## 八、常见问题

**Q：跑完一轮发现数字对不上？**
先跑任务⑥的核数器。**改一处要全盘搜引用**——本项目一次只凭记忆列了 6 个待改文件，
实际受影响 11 个（还漏了仓库里的 README）。

**Q：比对后列数塌缩到几十 bp？**
有序列过短导致比对错位。**用 `align` 阶段的列数闸门拦**（`--min-cols`）。
⚠️ **量列数别自己数行**——`awk 'NR==2'` 在序列按 60 字符折行时会永远返回 60（本项目实测踩过）。

**Q：`efetch` 返回 0 条？**
`rettype="gbc"` 返回的是 **XML**（`INSDSeq`），不是 GenBank flat file。用 `rettype="gb"`。
另外一次塞 22 个 id 会失败，**分批 ≤150** 稳定。

**Q：`"ICMP:18578"` 搜出 4 万条？**
纯数字被检索式拆开了（`ICMP AND 18578`）。**看到 count 大得离谱，第一反应是检索式坏了，不是数据多**。
改用号段检索 `JX009441:JX009560[ACCN]`。

**Q：某个物种判成「非单系」？**
先查分组——很可能是「一株多名」把它和别的种并到一起了（跑任务④）。
本项目实测 16 个多株物种里，14 个单系；剩下 2 个各有明确原因。

## 九、诚实的边界（这套工具做不到什么）

| 做不到 | 原因 |
|---|---|
| **标本型类群的等价链抽号** | 实测抽出率 **0%**（正文只写 `Holotype`）。需馆藏号正规化层或 GBIF |
| **全属一次性建树** | 数据散落在几百个提交里，号段法不适用（见第六节） |
| **不需要人工裁定** | J 规则候选**假阳性高**，只用于缩小候选集；`reconcile` 有 `--no-manual` 但那是跳过人工表，不是取消人工 |
| **给出「安全/无问题」的结论** | 机构词典不全时**只漏检、不误报** ⇒ 任何"错值条数"都是**下界** |
| **替代人工的分类学判断** | 「异名」可由异名表判定；「分类学修订（重新归属）」**判不了**——两个名字都是接受名，只能标「需查该菌株原始出处」 |

**口径约定（对外表述必须带）**：
凡引「N 条错值」，语义为**在可核验范围内确证的下界**；
凡引「错误率」，语义为**可核验子集内的下界比率**。

## 十、外部数据：哪些要自备

仓库里**只有少量示例数据**（`examples/data/`、`data/synonyms_colletotrichum.tsv`）。
下列文件**需自己准备**，指南里的路径只是占位：

| 文件 | 用途 | 从哪来 |
|---|---|---|
| `cbs_catalogue.tsv` | CBS 目录（号 → 模式地位标注） | CBS-KNAW 网站；本项目用的是自建抓取版（约 6.3 万行） |
| `SiM2022_fulltext.txt` | 框架论文全文 | 开放获取 PDF → 抽文本（**注意要抽 PDF 文本层，不能只存图片**） |
| `mycobank_full.tsv` | MycoBank 全库（判异名） | MycoBank 网站导出；本项目版为 426,834 行 / 61 MB |
| `NCBI_biocollections_full.csv` | 机构代码登记表 | NCBI Biocollections |
| `副表1_错误清单.tsv` 等 | 本项目自产的源表 | —— |

**没有 MycoBank 表也能跑**：`check_multiname.py` 会自动退化为「只做多名检测」，
三档里只出 `多名-3`（号重复使用，不依赖异名表），`多名-1`/`多名-2` 需要异名表才能区分。

**框架论文全文的坑**（本项目实测）：SiM 2022 的树图标签只存在于 **PDF 文本层**，
PMC 的 XML 里那张树是**图片**——按 XML 走会一行都取不到。
所以 `--sim-pdf` 要的是 **PDF 抽出的 txt**，不是 PMC XML。
